# 작업 일지

최초 버전 작업은 2025년 10월 13일~16일 나흘에 걸쳐 이루어졌으며, 마지막 날을 빼면 대략 하루에 2시간씩 작업했습니다. 소감 요약 뒤에 상세한 날짜별 작업 기록이 이어집니다.

## 소감 요약

- 어느 정도 이야기를 들어 Claude Code의 능력을 알고는 있었지만, 그럼에도 불구하고 감탄하게 되는 지점은 분명 있었습니다.
  - **전체적인 형태를 만드는 일**이나 **반복** 작업(테스트 파일 생성 등)에 유용할 것 같습니다.
  - 앞으로 작업 효율을 올리기 위해 필수적으로 사용하게 될 것 같은데, 프로젝트나 언어, 개발팀 구성 등에 따라 효과는 차이가 있을 것 같습니다.
    - 다만 그것이 (적어도 당분간은) N배는 아닐 것 같고 대부분의 경우 ~50%일 것 같습니다.
      - 그리고 일반적으로 소프트웨어 엔지니어의 업무 중 코드 작성이 차지하는 비율은 절반 이하라는 점을 고려하셔야 겠지요.
- 전반적인 코드 품질이 감내할 수는 있으나 만족스러운 정도는 아니었습니다. 다만 이건 제가 프런트엔드 전문가가 아니고, 바이브 코딩 전문가도 아니기 때문에 정확한 평가는 아니겠습니다.
  - 코드 품질 개선 및 자체적인 리팩터링을 위해 더 복잡한 도구들(스킬이라든가 MCP라든가)이나 여러 LLM의 교차 사용 등을 해봐야 할 것 같습니다.

## 10월 13일: 기본 동작

- 프로젝트 시작
  - Claude Code CLI로 plan모드 진입. "용례 찾기 웹앱을 만들거야."라고 하고 설명을 길게 여러 줄로 쓰려고 했는데, Cursor 안 터미널에서 shift-Enter가 잘 먹지 않아서 바로 입력이 들어가 버림. 튜토리얼에서 안티패턴으로 꼽는 짧은 문장으로 뜬구름잡는 일시키는 사람이 되어버림...
  - 그런데 클로드가 뭘 원하는지 객관식으로 보기를 제시하며 대화를 이끌어감. 예를 들어 백엔드가 필요한지, 어떻게 배포할건지 등을 물어봤던 것 같음. 체계적으로 반복할 거 아니면 이렇게 해도 큰 문제 없겠는걸...?
    - 이후에도 뭔가 내 결정이 필요할 때 여러 선택권을 번호로 제시하는 UX가 인상적이었음.
  - 그렇게 엉겁결에 웹앱 프로젝트가 만들어졌고 첫 커밋을 함(아직 기능 없음)

- 용례 데이터 준비(importer)
  - 국립국어원에서 제공하는 엑셀파일을 더 다루기 편한 CSV로 바꿈.
  - .xlsx -> CSV 변환은 내가 익숙한 파이썬으로.
  - ChatGPT에게 파이썬 스크립트를 만들어 달라고 함
    - .xlsx 파일을 주고 알아서 만들라고 시켰는데 이걸 Claude Code CLI에서 어떻게 하는지 몰라서 ChatGPT를 사용.

- 기본 검색 기능 구현
  - CSV를 주고 검색 기능을 만들라고 시켰더니 클로드가 바로 만들어줌. 심지어 UI도 목표했던 것과 비슷하게 표로 잘 그려서 이 구조를 끝까지 거의 바꾸지 않았음. (쫌 감탄)

- 테스트 추가
  - CI/CD 설정을 하려고 보니 테스트가 없음.
  - 테스트를 추가하라고 하니 unit test를 알아서 추가함.

- 배포 파이프라인 추가
  - 돈 안 드는 GitHub Pages를 쓸 생각이었음.
  - 배포 설정을 해달라고 하니 알아서 해줌. 하지만 깃헙 웹UI에서 내가 설정해야 하는 것들이 있는데 이런 건 친절하게 알려주지 않았음. (약간 실망) 다행히 Pages 설정을 해 본 적이 있어서 헤매지는 않음.

- CSV 고민
  - 배포해보니 CSV가 빌드에 빠져 있어서 클로드에게 지적하니 바로 수정함.
  - CSV 용량이 8MB(gzip압축 후 3MB) 정도여서 용량이 좀 큰 편인 것 같아서 plan 모드 켜고 고민 상담.
    - CSV를 json을 쓰면 용량이 줄어든다고 주장 => 그럴리 없음. -_-;;
    - gzip압축을 미리 해서 보내라고 함 => HTTP가 전송과정에서 압축하니 효과 거의 없음.
    - 캐시되니 괜찮다고 주장 => GitHub Pages는 캐시가 10분 고정이라서 괜찮지 않음.
      - 클로드 말을 믿지 말고 의심하자!!
  - 용량을 줄이는 건 쉽지 않아 보이니 캐시라도 더 길게 해 보자고 협의.
    - PWA(Progressive Web App)를 사용하면 직접 캐시를 컨트롤할 수 있다고 해서 구현 시킴.(되는 것 같은데 PWA를 잘 몰라서 확실하지는 않음...)

- 결과 너무 많은 경우 렌더링 개선
  - 'e' 같은 검색어는 결과가 수천 건이라 너무 느려지는 문제. 간단하게 검색어가 2글자 이상일 때만 보여주라고 지시하니 금방 잘 수정함. 테스트도 잘 추가했고, 최소 길이를 파라미터화하는 모습이 귀여웠음.(일반화할 거리를 열심히 찾는 신입 개발자 느낌...)

- README.md, CLAUDE.md
  - README는 사용자 타겟, CLAUDE.md는 AI 타겟 문서인데 작업을 해도 이 파일들을 그에 맞게 갱신하지 않음.(사실 사람 개발자도 그렇다...) 잘 챙겨서 업데이트하라고 지시.
    - CLAUDE.md를 알아서 잘 업데이트하라는 지시를 여러 방법으로 해 봤지만 잘 지켜지지 않았음.(더 쎄게 말해야 하나?)

## 10월 15일: 복잡한 기능 도전

- 검색 랭킹
  - 완전 일치가 위로 나오도록 결과를 정렬하는 기능
    - 구현 과정에서 클로드가 "표제어가 여러 단어인 경우 단어에 완전 일치 하는 경우"도 처리할 수 있는 구조를 만들었다고 자랑(?)함.
    - 그래서 그것까지 다 구현하라고 하고 보니 코드 구조가 아주 비효율적임.
  - 각 조건별로 부분 리스트를 만드는 방식으로 구현하라고 지시. 
    - 조건이 좀 복잡해지니까 헤매기 시작. 계속 코드를 고치긴 하지만 테스트가 계속 실패.
      - 1~2분쯤 혼자 헤매다가 "너무 복잡해졌으니 지우고 다시 하겠다"며 스스로를 비판함.
      - 1~2분쯤 더 기다렸더니 드디어 테스트 통과.
    - 코드를 봤더니 필요없는 코드가 많고 지저분...
      - 뭐라고 시키면 또 헤맬 것 같아서 해당 부분을 내가 직접 정리.(주로 코드 삭제)
  - 시간을 많이 주거나 Opus에게 시켜봤으면 좀 달랐을 수도 있을 것 같은데 몇 분 동안 가만히 지켜보는 게 (성격 문제로) 쉽지는 않았음.
- UI 리팩터링 및 개선
  - 간단한 리팩터링은 잘 함. 테스트 확인 및 갱신도 비교적 잘 함.
  - 타이핑하면서 화면이 깜빡이는 게 싫어서 2글자 이상 입력하라는 메시지를 0.5초 후에 띄우도록 타이머 추가.
    - 백엔드 개발자인 내가 보기에는 복잡한 기능일 것 같았으나 의외로 금방 함.
- 검색 결과에 검색어 하이라이팅 추가
  - 이것도 복잡할 줄 알았는데 생각 외로 빠르게 처리함.
  - 특히 `s.split(regex)`에서 regex에 capture group(괄호)을 넣으면 split의 capture된 결과도 결과 배열에 반환된다는 점을 영리하게 이용했는데, 나는 `split()`에 이런 기능이 있으리라고는 상상하지 못했음.

## 10월 16일: 클라우드 삽질의 날

- 오늘의 목표는 엑셀파일을 하루에 한 번씩 업데이트하도록 자동화하는 것

1. GitHub Actions
   - action을 하루에 한 번씩 스케줄해서 수행하도록 설정하는 건 금방 완료.
   - 그런데 왜인지 스크립트가 실패함.
     - `curl`에서 Remote host가 연결을 끊으심...
     - 국립국어원 엑셀파일 다운로드가 GitHub Actions가 도는 서버에서 막혀 있는 듯...
1. GCP에서는...?
   - AWS에 들어가서 Cloud Shell로 `curl`을 날려보니 잘 됨.
   - 하지만 개인적으로 GCP가 더 익숙하기 때문에 GCP Cloud Run으로 업데이트를 해 보기로 결정
   - ChatGPT와 논의하며 이것저것 설정을 하다가 혹시나... 싶어 GCP Cloud Shell로 `curl`을 날려보니 막혀 있음...
1. AWS
   - 다시 AWS Lambda로 선회. ChatGPT에서 python 런타임을 추천하며 코드를 써 주길래 이것저것 설정(aws CLI깔고, 인증 키, SecretManager, IAM, EventBridge...)
   - 그런데 실행시켜 보니 Lambda python runtime에 사전 업데이트시 필요한 `git`이 없었음... ChatGPT에게 잔소리를 살짝 하고, 컨테이너 기반 Lambda로 작전 변경
   - ChatGPT와 함께 이미지 굽고 이래저래 다 설정하고 돌려보니... 또 `curl`에서 실패함... 사실 cloud provider들에서는 다 막혀있는게 맞는 것 같음. Cloud Shell에서 뚫려 있는 게 이상한 상황이었던 듯함.

> 결론: 국립국어원에서 정식으로 제공하는 OpenAPI를 쓰자. 이건 안 막혀 있는 것 같음.

여기까지 시간이 많이 흘러서 일단 중지. 추후에 OpenAPI로 최근 등록된 항목을 불러오는 식으로 개선해야 할 듯.
